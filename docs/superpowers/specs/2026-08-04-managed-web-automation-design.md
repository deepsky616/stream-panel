# 스트림 패널 업무용 브라우저 자동 이동 설계

작성일: 2026-08-04

## 1. 목적

윈도우의 나이스와 에듀파인 웹 업무 키를 브라우저 확장 기능 없이 실행한다. 스트림 패널이 개인 브라우저와 분리된 업무용 엣지 또는 크롬을 직접 실행하고, 브라우저 개발 도구 통신 규칙으로 허용된 업무 화면까지만 이동한다.

다음 네 업무를 지원한다.

- 나이스 복무
- 나이스 출장
- 에듀파인 기안
- 에듀파인 품의

로그인, 인증서 선택, 업무 내용 입력, 저장, 제출, 상신, 승인과 결재는 사용자가 직접 수행한다.

## 2. 승인된 제품 결정

- 업무용 엣지를 기본값으로 제공한다.
- 업무용 크롬도 같은 수준으로 선택할 수 있게 한다.
- 브라우저마다 개인 프로필과 분리된 업무 전용 프로필을 사용한다.
- 브라우저 제어는 파이프 연결을 먼저 시도한다.
- 파이프가 지원되지 않을 때만 무작위 로컬 포트로 한 번 다시 연결한다.
- 고정된 원격 제어 포트는 사용하지 않는다.
- `AppConfig`에 `educationOfficeCode`를 추가한다.
- 기존 IPC 채널 이름과 입력·출력 형식은 유지한다.
- 기존 브라우저 확장 연결 서버와 앱에 포함된 확장 기능은 제거한다.
- 맥에서는 웹 업무 자동 이동을 제공하지 않는다.

## 3. 해결하려는 기존 문제

### 3.1 원클릭 업무 포털 방식의 약점

- 예측 가능한 고정 제어 포트를 사용한다.
- 공식 사용 흐름이 엣지에 묶여 있다.
- 브라우저 제어 권한이 넓어 로그인된 다른 사이트까지 접근할 가능성이 있다.
- 브라우저 설정 파일에 외부 프로그램 실행 허용 값을 직접 넣는다.
- 접속 시간을 계속 자동 연장하면 사람이 없는 상태에서도 업무 세션이 유지될 수 있다.
- 화면 구성이 바뀌었을 때 단계별 원인과 해결 방법이 충분히 드러나지 않을 수 있다.
- 앱이 비정상 종료되면 업무용 브라우저와 프로필 잠금이 남을 수 있다.

### 3.2 현재 스트림 패널 방식의 약점

- 사용자가 개발자 모드를 켜고 압축 해제 확장 기능을 직접 추가해야 한다.
- 경기 교육청 주소만 허용한다.
- 고정된 메뉴 글자를 순서대로 누를 뿐 목표 화면의 준비 상태를 충분히 확인하지 않는다.
- 업무 포털과 나이스 공지창, 이미 열린 신청창과 별도 기안 편집기를 제대로 다루지 못한다.
- 브라우저 확장 기능, 로컬 연결 서버와 앱 실행기가 나뉘어 오류 지점이 많다.
- 업무 키에 선택한 일반 브라우저 프로필을 제어하므로 개인 브라우저와 업무 자동화의 경계가 약하다.

## 4. 범위와 제외 범위

### 4.1 포함

- 전국 17개 교육청의 업무 포털, 나이스와 에듀파인 공식 주소 목록
- 교육청과 브라우저별 전용 프로필
- 엣지와 크롬 실행, 제어 연결, 종료와 상태 확인
- 나이스·에듀파인 탭 찾기와 공식 주소 예비 이동
- 공지창과 안전한 안내창 닫기
- 네 업무의 상태 기반 화면 이동
- 에듀파인 기안 편집 프로그램 설치 확인과 새 창 감지
- 원인과 해결책을 함께 주는 한국어 오류 안내
- 기존 웹 업무 키와 멀티 액션의 설정 이전

### 4.2 제외

- 아이디, 암호와 인증서 자동 입력
- 저장, 제출, 승인, 상신과 결재 자동 실행
- 사용자가 입력한 임의 선택자나 자바스크립트 실행
- 기본 엣지·크롬 프로필이나 이미 열린 개인 브라우저 제어
- 맥의 나이스·에듀파인 자동 이동
- 무인 상태의 접속 시간 자동 연장
- 교육청 사이트의 권한 제한과 보안 프로그램 우회

## 5. 자료 구조

### 5.1 교육청 코드

`EducationOfficeCode`는 다음 값만 허용한다.

```ts
type EducationOfficeCode =
  | 'sen' | 'goe' | 'gne' | 'pen' | 'dge' | 'dje'
  | 'gbe' | 'sje' | 'use' | 'ice' | 'gen' | 'jne'
  | 'jbe' | 'cne' | 'cbe' | 'gwe' | 'jje';
```

`AppConfig.educationOfficeCode`의 기본값은 기존 경기 주소와 맞는 `goe`다. 저장 자료에 필드가 없으면 이전 과정에서 `goe`를 채운다.

### 5.2 기존 타입 유지

`WebWorkflowSpec`, `WebConnectorBrowserId`와 `WebConnectorStatus`의 형태는 바꾸지 않는다.

`WebConnectorStatus`는 다음 뜻으로 사용한다.

- `paired`: 해당 교육청과 브라우저의 업무용 프로필을 만들고 제어 연결에 한 번 성공했음
- `connected`: 현재 스트림 패널이 소유한 브라우저와 제어 통로가 살아 있음
- `extensionVersion`: 더 이상 채우지 않음
- `lastSeenAt`: 마지막으로 제어 통로가 정상 응답한 시각

웹 업무 키의 `webWorkflow.browserId`가 업무용 엣지 또는 크롬을 고른다. 일반 URL 키의 `BrowserSpec` 동작은 바꾸지 않는다.

### 5.3 민감하지 않은 준비 상태

`userData/web-connector/managed-state.json`에는 다음 정보만 저장한다.

- 자료 형식 버전
- 교육청과 브라우저별 마지막 제어 연결 성공 시각
- 예전 확장 기능 중단 안내를 표시했는지 여부

포트, 프로세스 번호, 웹소켓 주소, 전체 URL, 로그인 자료와 세션 값은 저장하지 않는다. `WebConnectorStatus`의 `paired`와 `lastSeenAt`은 현재 선택한 교육청의 이 파일에서 계산한다.

## 6. 교육청 주소 목록

각 교육청은 이름, 코드, 업무 포털, 나이스와 에듀파인 주소를 가진다. 기본 규칙은 다음과 같다.

```text
업무 포털: https://{code}.eduptl.kr/
나이스:    https://{code}.neis.go.kr/
에듀파인:  https://klef.{code}.go.kr/
```

경북 에듀파인은 `https://klef.gbe.kr/` 예외를 사용한다. 모든 주소는 코드에 직접 적은 고정 목록에서만 만들어지며 사용자 입력으로 호스트를 바꿀 수 없다.

교육청을 바꾸면 모든 웹 업무 키의 시스템 첫 주소를 새 교육청의 공식 주소로 갱신한다. 키의 식별자, 이름, 아이콘, 브라우저 선택과 멀티 액션 참조는 유지한다.

## 7. 구성 요소

```text
services/webConnector/
├─ index.ts
├─ windows.ts
├─ macos.ts
├─ browserProcess.ts
├─ sessionManager.ts
├─ officeCatalog.ts
├─ diagnostics.ts
├─ cdp/
│  ├─ transport.ts
│  ├─ pipeTransport.ts
│  ├─ portTransport.ts
│  └─ protocol.ts
└─ workflows/
   ├─ engine.ts
   ├─ common.ts
   ├─ neis.ts
   └─ edufine.ts
```

### 7.1 `index.ts`

기존 `WebConnectorService` 공개 경계를 유지한다. 실행 환경에 따라 윈도우 구현 또는 안전한 맥 기본 구현을 고른다.

### 7.2 `windows.ts`

업무 실행 요청을 교육청, 브라우저와 업무 종류로 검증하고 세션 관리자와 업무 엔진을 연결한다. 플랫폼 전용 파일과 실행 파일 탐색은 이 경계 밖으로 새지 않는다.

### 7.3 `browserProcess.ts`

- 알려진 엣지와 크롬 설치 위치만 사용한다.
- 실행 파일 이름과 브라우저 종류가 일치해야 한다.
- `spawn`에 인자 배열을 전달하고 셸은 사용하지 않는다.
- 교육청과 브라우저별 프로필 경로를 만든다.
- 사용자가 임의 플래그를 넣을 수 없게 한다.
- 스트림 패널이 만든 자식 프로세스만 종료한다.

### 7.4 `sessionManager.ts`

- 교육청과 브라우저 조합마다 세션 하나만 허용한다.
- 동시에 들어온 실행 요청을 직렬화한다.
- 살아 있는 세션은 재사용한다.
- 연결이 끊기면 업무를 시작하기 전에 한 번만 다시 실행한다.
- 교육청을 바꾸면 이전 교육청에서 스트림 패널이 실행한 세션을 안전하게 닫는다.
- 앱 종료 시 브라우저 종료 명령을 보내고 자식 프로세스 종료를 확인한다.
- 소유권을 증명할 수 없는 기존 프로세스는 강제로 종료하지 않는다.

### 7.5 `cdp` 폴더

브라우저 개발 도구 메시지 전송과 응답 연결만 담당한다. 렌더러나 사용자 입력으로 명령 이름, 자바스크립트 또는 선택자를 받지 않는다.

### 7.6 `workflows` 폴더

업무별 상태 단계, 안전한 메뉴 후보, 성공 조건과 제한 시간을 정의한다. 브라우저 실행이나 창 관리는 알지 못한다.

## 8. 브라우저 실행과 연결

### 8.1 프로필 경로

```text
userData/web-browsers/{educationOfficeCode}/{browserId}/
```

개인 브라우저의 기본 자료 폴더와 기존 프로필 경로는 절대 사용하지 않는다.

### 8.2 파이프 우선

첫 실행은 사용자 자료 폴더, 새 창과 원격 제어 파이프만 포함한 고정 인자 목록을 사용한다. 브라우저 응답이 제한 시간 안에 오지 않으면 스트림 패널이 소유한 자식 프로세스만 닫고 무작위 포트 방식으로 한 번 다시 실행한다.

### 8.3 무작위 포트 예비 연결

예비 실행은 `--remote-debugging-port=0`을 사용한다. 브라우저가 전용 프로필 안에 만든 `DevToolsActivePort`만 읽는다.

다음을 모두 검증해야 한다.

- 파일이 승인된 전용 프로필 경로 바로 아래에 있음
- 포트가 정수이고 1024부터 65535 사이임
- 웹소켓 식별자가 정해진 문자와 길이만 가짐
- 주소가 `127.0.0.1`임
- 응답한 브라우저 종류가 요청한 엣지 또는 크롬과 일치함

고정 포트와 외부 인터페이스 수신은 허용하지 않는다.

## 9. 제어 권한 제한

- 선택한 교육청의 업무 포털, 나이스와 에듀파인 호스트만 대상 탭으로 인정한다.
- 새 탭 생성은 해당 세 공식 주소로만 허용한다.
- 허용 호스트 밖으로 이동하면 즉시 업무를 중단한다.
- 대상 탭의 전체 주소는 기록하지 않고 호스트만 기록한다.
- 쿼리 문자열, 세션 값, 쿠키와 저장 자료를 요청하거나 기록하지 않는다.
- 브라우저 개발 도구 명령은 코드에 고정된 허용 목록만 쓴다.
- 렌더러에서 임의 스크립트, 좌표, 선택자와 개발 도구 명령을 받을 수 없다.

## 10. 업무 실행 흐름

### 10.1 공통 흐름

```text
키 실행
→ 교육청·브라우저·업무 조합 검증
→ 업무용 브라우저 준비
→ 로그인 상태 확인
→ 나이스 또는 에듀파인 탭 준비
→ 공지창 안전 처리
→ 고정 상태 단계 실행
→ 목표 입력 화면 검증
→ 브라우저 또는 편집기 창을 앞으로 가져옴
→ 사용자 입력 전에 멈춤
```

로그인이 필요하면 업무 포털을 앞으로 가져오고 사용자가 직접 로그인한 뒤 키를 다시 누르도록 안내한다. 암호 입력을 기다리며 명령을 무기한 보관하지 않는다.

### 10.2 안전한 후보 선택

메뉴 후보는 다음 조건을 모두 만족해야 한다.

- 실제 화면에 보임
- 크기가 0보다 큼
- 비활성 또는 숨김 상태가 아님
- 업무 단계의 고정된 이름과 정확히 일치하거나 승인된 별칭임
- 저장, 제출, 상신, 승인, 결재 또는 확정 금지 문구를 포함하지 않음

문자열이 일부 포함된다는 이유만으로 후보를 고르지 않는다. 후보가 둘 이상이면 단계가 모호한 것으로 보고 중단한다.

### 10.3 누르기와 성공 확인

안전한 요소에는 먼저 일반 사용자 누르기와 가까운 브라우저 입력 사건을 전달한다. 일반 DOM 누르기는 해당 화면이 그것만 받는 것으로 검증된 단계에서만 사용한다.

각 단계는 누르기 뒤 다음 중 하나로 성공을 확인한다.

- 기대한 메뉴가 보임
- 기대한 입력창 제목이 보임
- 기대한 업무 탭이 선택됨
- 기대한 새 창이 생김
- 주소 호스트와 화면 표식이 함께 맞음

성공 조건이 확인되지 않으면 다음 단계로 넘어가지 않는다.

### 10.4 업무별 끝 지점

- 나이스 복무: 개인근무상황관리의 근무상황신청 입력창
- 나이스 출장: 개인출장관리의 출장신청 입력창
- 에듀파인 기안: 공용 표준서식 편집기 창
- 에듀파인 품의: 학교회계 품의등록 입력 화면

끝 지점에서 저장, 승인 요청, 결재 요청과 결재 올림은 누르지 않는다.

## 11. 에듀파인 기안 편집기

윈도우 전용 구현에서 알려진 기안 편집 프로그램 등록 상태를 안전하게 확인한다. 실행 확인 명령은 인자 배열로 호출하고 셸을 사용하지 않는다.

브라우저의 외부 프로그램 허용 설정 파일을 스트림 패널이 직접 수정하지 않는다. 사용자가 브라우저의 공식 확인창에서 한 번 승인한다.

표준서식 선택 전 열린 편집기 창 목록을 저장하고, 선택 뒤 새로 생긴 창만 결과로 인정한다. 새 창이 확인되면 앞으로 가져오고 업무용 브라우저는 그대로 둔다.

## 12. 접속 시간 정책

접속 시간을 백그라운드에서 무한히 연장하지 않는다. 사람이 없는 상태에서 업무 세션이 계속 유지되는 것을 막기 위해 다음 정책을 쓴다.

- 스트림 패널은 공식 접속 종료 시간을 읽을 수 있을 때만 경고한다.
- 연결된 업무용 브라우저가 있을 때 1분 간격으로 표시 시간만 확인한다.
- 종료가 가까우면 업무용 브라우저를 앞으로 가져오고 한국어 안내를 표시한다.
- 실제 접속 연장은 사용자가 공식 연장 버튼으로 확인한다.
- 시간이나 공식 연장 화면을 찾지 못하면 새로고침하거나 임의 요청을 보내지 않는다.

## 13. 오류와 복구

### 13.1 오류 종류

- 브라우저 없음
- 전용 프로필 사용 중
- 제어 통로 연결 실패
- 로그인 필요
- 허용되지 않은 주소
- 화면 구성 변경 또는 업무 권한 없음
- 단계 제한 시간 초과
- 기안 편집 프로그램 없음
- 사용자가 브라우저 또는 창을 닫음

모든 오류 문구는 원인과 사용자가 할 일을 함께 준다.

### 13.2 복구 원칙

- 제어 연결은 파이프 실패 뒤 무작위 포트로 한 번만 다시 시작한다.
- 브라우저가 예기치 않게 종료되면 업무 시작 전 한 번만 다시 실행한다.
- 화면 단계는 같은 안전 후보가 하나일 때만 제한된 횟수로 다시 확인한다.
- 세 번 실패하거나 후보가 모호하면 즉시 중단한다.
- 실패한 대상 브라우저를 앞으로 가져와 사용자가 직접 계속할 수 있게 한다.
- 소유하지 않은 프로세스 종료, 프로필 삭제와 설정 초기화는 자동으로 하지 않는다.

## 14. 기존 확장 기능 이전

- 기존 `browser-extension/`은 윈도우 앱 묶음과 개발 실행 경로에서 제거한다.
- `127.0.0.1:38473` 연결 서버는 시작하지 않는다.
- 예전 연결 상태 파일은 읽지 않으며 자동 삭제하지 않는다.
- 설정 화면에서 확장 기능 설치와 연결 안내를 제거한다.
- 기존 확장 기능은 브라우저에서 자동으로 지울 수 없으므로 더 이상 필요하지 않다는 안내를 한 번 보여 준다.
- README에는 사용자가 원할 때 엣지와 크롬에서 예전 확장 기능을 직접 제거하는 절차를 적는다.

## 15. 기존 IPC 호환

IPC 이름과 입력·출력 형태는 유지한다.

### `web-connector:status`

업무용 엣지와 크롬의 프로필 준비 및 현재 연결 상태를 반환한다.

### `web-connector:test`

선택한 업무용 브라우저를 실행하거나 재사용하고 제어 통로, 브라우저 종류와 현재 교육청 공식 주소 접근을 확인한다. 로그인 성공 자체를 시험 통과 조건으로 삼지 않는다.

### `web-connector:open-setup`

- `pair`: 선택한 업무용 브라우저의 업무 포털 로그인 화면을 연다.
- `folder`: 민감 정보를 제외한 진단 기록 폴더를 탐색기에 표시한다. 브라우저 프로필 폴더는 열지 않는다.
- `extensions`: 더 이상 확장 기능이 필요하지 않다는 안전한 안내를 반환한다.

렌더러의 새 화면은 `extensions`를 호출하지 않지만 이전 렌더러와의 호환을 위해 입력값은 유지한다.

## 16. 액션 실행과 멀티 액션

웹 업무 키는 일반 URL 브라우저 실행 경로를 거치지 않는다. `webWorkflow.browserId`에 따라 업무용 브라우저 세션에 고정 업무를 넣는다.

요청이 안전하게 접수되면 패널 실행은 즉시 성공을 반환하고 화면 가림 정책에 따라 패널을 숨긴다. 실제 업무 이동 결과는 기존 알림 경로로 보낸다.

멀티 액션은 기존처럼 웹 업무 요청 접수를 해당 단계의 성공으로 본다. 업무 화면 완료를 기다리거나 그 뒤 저장·제출 단계를 자동으로 이어 가지 않는다.

업무용 브라우저를 준비하지 못하면 공식 시스템 첫 주소를 운영체제 기본 브라우저로 열지 않는다. 개인 브라우저로 로그인 자료가 섞이는 것을 막기 위해 업무용 브라우저를 직접 열고 원인을 안내한다.

## 17. 설정 화면

윈도우의 `웹 업무 연결` 탭은 다음을 제공한다.

- 소속 교육청 선택
- 업무용 엣지 카드와 추천 표시
- 업무용 크롬 카드
- 브라우저별 `준비됨`, `실행 중`, `로그인 필요`, `오류` 상태
- `업무용 브라우저 열기`
- `연결 시험`
- 오류가 있을 때만 `문제 해결 폴더 열기`
- 로그인과 인증서 선택은 사용자가 직접 한다는 안내
- 저장·제출·상신·승인·결재를 자동 실행하지 않는다는 안내

교육청 변경 시 현재 업무용 브라우저를 닫고 새 교육청 프로필을 사용할 것임을 알려 준다.

- 크롬 전용 프로필 첫 로그인과 다시 실행
